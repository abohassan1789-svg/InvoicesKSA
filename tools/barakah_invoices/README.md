# فواتير وسندات «زيادة البركة» — شركة النقيب للإنارة الحديثة

`barakah_invoices.sql` يضيف لشركة «زيادة البركة التجارية»:

- العميل «شركة النقيب للإنارة الحديثة» (الرقم الضريبي 311103749200003، الرقم الموحد 7011567356،
  جدة - حي البلد - شارع بامحرز - مبنى 2779 - الرقم الفرعي 6234 - 22233) لو مش موجود.
- 10 فواتير مبيعات آجلة (مسودات) بأرقام وتواريخ ومبالغ شيت الإكسل
  (736–877، إجمالي 251,300 قبل الضريبة + 37,695 ضريبة = 288,995)، أصنافها أصناف حرة
  من قائمة الأصناف الكهربائية (7 أصناف لكل فاتورة عشان تطلع صفحة واحدة في النموذج 22).
- 8 سندات قبض (113–171، تحويل بنكي) بإجمالي 288,995، وكل سند «وذلك قيمة» بيذكر الفواتير اللي بيسددها
  بالترتيب. الفواتير آجلة عشان كشف حساب العميل يطلع رصيده صفر.

لازم `tools/barakah_company/barakah_company.sql` يتشغل الأول (بيضيف الشركة بختمها).
كله في transaction واحدة، ولو أي رقم فاتورة لنفس الشركة أو أي رقم سند موجود بيقف من غير ما يغيّر حاجة.
بيانات ZATCA (UUID / XML / QR) ما بتتكتبش؛ البرنامج بيعملها لما الفاتورة تتحفظ من الشاشة.

التشغيل على داتابيس البرنامج:

```
psql -h localhost -U postgres -d <اسم الداتابيس> -v ON_ERROR_STOP=1 -f tools/barakah_company/barakah_company.sql
psql -h localhost -U postgres -d <اسم الداتابيس> -v ON_ERROR_STOP=1 -f tools/barakah_invoices/barakah_invoices.sql
```

- `items.json`: قائمة الأصناف (223 صنف، الكود والاسم والتكلفة) من ملف `electrical_items.xlsx`.
- `alloc.py`: بيختار أصناف وكميات كل فاتورة بحيث مجموعها يساوي مبلغ الفاتورة بالظبط (محتاج `ortools`) → `alloc.json`.
- `gen_sql.py`: بيولّد ملف الـ SQL من `alloc.json` وبيتأكد إن إجماليات كل فاتورة والسندات مطابقة للإكسل.
